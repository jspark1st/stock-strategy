# BTC 펀딩 캐리 — 주식↔크립토 교차 아이디어 구현

> **BTC 별도 트랙 소속(main 병합됨).** CLAUDE.md 대로 BTC 무기한 트랙은 같은 repo·서버를 쓰되
> **주식 스코어링·크론·대시보드와 완전 분리**돼 공존한다. 이 모듈도 신규 파일만 추가하고 주식
> 파이프라인을 안 건드린다(오버나이트 롱 단일 전략 = 북극선 그대로). **관측·실험 단계(L0/L1)** 이며
> 실주문·자동집행은 없다 — 다레짐 재검증 전 실거래·레버리지 확대 금지.
> 두 트랙(overnight_report 주식 · hyodobot 크립토)의 **강점 결합** 실험이다.

## 아이디어 (왜 이걸 만들었나)

2026-08-25 대화에서 도출: 지표(RSI/MACD/EMA…) 최적화는 일봉·1시간봉·임계값·역추세 어디서도
**비용 후 OOS 알파가 없었다**(곡선맞춤). 재료(OHLCV)가 이미 가격에 반영돼서다. 반면 **차트 밖
구조**인 **펀딩 캐리**는 유일하게 (+)이고 **시장중립**이었다.

- **주식 트랙이 준 것(규율):** walk-forward·비용차감·저회전·정직한 성적(n<40 측정중)·구조>지표.
- **크립토 트랙이 준 것(실행부):** hyodobot의 24/7 주문·리스크·잔고검증·거래소 연동.
- **결합:** 주식의 *구조적 프리미엄 수취 insight* → 크립토의 *펀딩 캐리* 에 적용, hyodobot 실행부가 집행.

## 전략 (하나다 — 시장중립 패시브, 방향 예측 아님)

펀딩 양수 = 롱이 숏에게 지급 → **숏 무기한선물 + 롱 현물**(델타중립)이 8시간마다 수취.
방향을 안 맞혀도 되는 **구조적 수익**이라 견고(지표처럼 곡선맞춤 아님). 전략은 **항상 패시브 보유**
하나이며, `carry_signal`은 별도 전략이 아니라 **'지금 신규 자본을 넣을 만큼 캐리가 두꺼운가'**
진입 타이밍 필터일 뿐(얇으면 대기).

## 라이브 실측 (2026-08 기준 · 페이지네이션 수정 후)

> ⚠️ 초기 커밋의 **+2.3% / 0.46년 / 양수 72%** 는 **잘린 표본(166일 1페이지)** 이었다. 바이낸스가
> 요청당 ~500행만 주는데 `len(rows)<1000` 로 멈춰 1페이지만 돌던 버그. 페이지네이션 수정 후:

- n=**3000 · 2.74년** · 펀딩 양수 **85%**
- 패시브 순 연환산: **명목 +8.2% → 자본대비 +4.1%/년**(현물+숏 증거금으로 자본 ≈2배 → ÷2)
- 능동("양수일 때만") 명목 **−56.7%**(전환 405회) — 회전 비용에 죽음(**저회전 패시브가 옳다**)
- **구간 분해(레짐 지속성, 자본대비/년): 7.8% → 3.4% → 2.4% → 1.2%** (양수비율 98%→72%)
  → **캐리가 시간이 갈수록 압축 중.** 헤드라인 한 숫자로 보면 안 되는 이유.

- **베이시스 반영 현금캐리(펀딩 − Δ베이시스): 명목 +22.4% = 펀딩만 +22.4%** → 차이(경계항) ≈ 0
  → 무기한선물은 만기가 없어 **펀딩이 수익의 정확한 근사**임을 실측 확인. 베이시스는 수익이 아니라
  **MTM 리스크**(8h 변동 std ≈ 0.023% · 최악 MTM 낙폭 ≈ −0.48%)로 정량화됨.

**정직한 한계:** 작고(예금~국채 수준) **줄고 있다.** 단일 상승레짐. 불장선 커지고 하락장선 압축/역전.
자본 2배 묶임·청산·베이시스 MTM 리스크. **다레짐 재검증 전 레버리지·실거래 확대 금지.**

## 효도봇 연동(다음 단계, 미구현)

`run_btc_carry.py --json out/btc_carry.json` → `signal.position` 을 효도봇 실행부가 읽어
중립 포지션(숏 perp + 롱 spot)을 집행. **여기까지는 신호 산출(L0/L1), 실주문 없음.**
효도봇 백테스트에 **비용 모델 + 시계열 검증**이 없으므로(현재 gross·K-Fold), 실거래 전
이 규율로 재검증 필요.
