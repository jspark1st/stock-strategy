# 트리아지 — 누적 비평 → 수정 → 폐쇄 (루프의 다리)

`/checkup`·`/quality` 는 **코드를 새로 감사**한다. 이 스킬은 다르다: 매 회차 쌓인 **자가비평
백로그(`report_review`)를 출발점**으로, 실행가능한 것만 골라 고치고 **닫는다**. 이게 "누적 결과로
개발 발전"의 실체 — 사람이 하던 백로그↔수정 다리를 자동화한다.

## 1. 백로그 읽기

```bash
.venv/bin/python scripts/review_digest.py --no-telegram
cat out/review_backlog.md
```

- **🔧 실행가능**: 지금 코드로 고칠 표시·논리·품질 결함 → 이번 트리아지 대상.
- **⏳ 수용/데이터대기**(`ACCEPTED_CODES`: btc_gate_block·no_discrimination·calib_slope_floor·
  sample_short·mixed_signals·news_dead): **건드리지 마라.** 코딩이 아니라 다레짐 데이터·설계다.
- **해결률**(open/resolved): 같은 항목이 안 닫히고 쌓이면 노이즈, 새 항목이 나고 닫히면 루프 작동.

## 2. 각 실행가능 발견을 분류 (고치기 전에)

발견마다 라이브로 **재현**하고 셋 중 하나로:

1. **지금 고칠 것** — 표시(게이트/지평/n<40 정직성)·논리 모순·무성 실패·가드 공백. → 3으로.
2. **오분류(실은 데이터 대기)** — LLM 이 code 를 잘못 붙였다(예: '실적 부재'를 horizon_divergence 로).
   실제로는 n<40·판별미확보라 코딩 대상 아님 → **고치지 말고** `--resolve` 로 닫되 이유를 보고.
3. **이미 고쳐짐** — 과거에 수정됐는데 옛 행이 안 닫힌 것 → `--resolve` 로 닫는다.

## 3. 고치기 (quality-fanout 규율)

- 발견이 여러 개면 **`quality-fanout` 에이전트에 위임**(병렬 재현·적대 검증). 한두 개면 인라인.
- **최소 수정 + 회귀 테스트 1개**(그 발견 code 가 다시 안 나게 고정). `.venv` 로 전체 pytest.
- 표시·논리·품질만. **스코어링/게이트 임계·확률 산식·BTC 게이트는 건드리지 마라**(→ /quality '하지 말 것').

## 4. 닫기 (루프 폐쇄)

고쳤거나 오분류/이미해결로 판정한 code 를 닫는다:

```bash
.venv/bin/python scripts/review_digest.py --resolve <code>
```

닫은 것·이유를 보고. 안 닫은 실행가능 항목은 왜 못 닫았는지(데이터 필요·설계 결정 대기) 남긴다.

## 5. 보고

- 실행가능 N건 중: 고침 X · 오분류 닫음 Y · 남김 Z(사유).
- 해결률 변화(전/후). 회귀 테스트 추가분. 라이브 재렌더·배포·커밋은 **사용자 지시가 있을 때만**.

## 하지 말 것

- 수용/데이터대기(ACCEPTED_CODES) 항목을 '고치려' 코드 손대기 — 데이터·설계다.
- 통과율·해결률을 올리려 임계 완화·백로그 임의 삭제(닫기는 실제 수정/오분류 판정 후에만).
- vol_tilt·미국선물·news 가중 되돌리기 · BTC 게이트 완화 · git commit/push/실주행 · `.env` 출력.
