# Codex / Cursor 역할별 구현 프롬프트

각 프롬프트는 독립 실행 가능하도록 작성되어 있다. 순서대로 진행하되, 1과 2는 병렬 가능하다.
아침 파이프라인(`market-open-sentiment`)이 이미 있다면 같은 리포지토리·같은 DB에 얹는다.

---

## 1. 수집기 (collector)

```
FastAPI + APScheduler 기반 한국 주식시장 마감 데이터 수집기를 만들어줘.

수집 대상과 시각 (KST, 평일만):
- 15:20 지수 스냅샷 (마감 동시호가 직전 KOSPI/KOSDAQ)
- 15:35 전종목 종가 스냅샷 → 상승/하락 종목 수, 상한가/하한가 수, 거래대금 집계
- 15:40 내 계좌 체결내역 조회 → trades 테이블 자동 채움
- 15:45 투자자별 매매동향 잠정치 (외국인/기관/개인/프로그램)
- 16:00~18:00 5분 간격 DART OpenAPI list.json 폴링 → 유상증자/전환사채/감자/대주주매도 키워드 필터
- 18:10 투자자별 매매동향 확정치 → 잠정치 레코드 갱신

증권사는 한국투자증권 Open API를 쓴다. 토큰은 24시간 캐싱하고 만료 시 자동 재발급.
DART OpenAPI 키는 환경변수 DART_API_KEY.

요구사항:
- 모든 원본 응답을 data/raw/{YYYY-MM-DD}/{job_name}.json 으로 저장
- 한국거래소 휴장일 테이블을 확인해 휴장일이면 모든 잡 즉시 return
- 실패 시 3회 지수 백오프 재시도, 최종 실패는 missing 목록에 기록
- PostgreSQL 저장. 스키마는 daily_market, daily_flows, trades 테이블 (별첨 스키마 참고)
- 투자자별 매매동향은 provisional 플래그로 잠정/확정 구분 저장
- 타입 힌트 전부 붙이고 pydantic 모델로 응답 검증
```

## 2. 스코어링 엔진 (scoring)

```
한국 주식시장 마감 점수를 계산하는 순수 함수 모듈을 만들어줘. 외부 IO 없이 입력 dict만 받는다.

6개 서브스코어를 각각 0~100으로 계산:
1) 종가 강도 (가중치 0.20): close_pos = (종가-저가)/(고가-저가), chg_pct, 5일선 상회 플래그
   close_score = 50 + 40*(close_pos-0.5) + 6*clamp(chg_pct,-3,3) + 8*ma5_flag
2) 시장 폭 (0.20): adv_ratio, limit_net = 상한가수 - 하한가수
   breadth_score = 50 + 80*(adv_ratio-0.5) + 2*clamp(limit_net,-10,10)
3) 투자주체 수급 (0.25): 외국인/기관/프로그램 순매수 억원 단위
   flow_score = 50 + 12*clamp(frn/3000,-2,2) + 8*clamp(ins/3000,-2,2) + 5*clamp(prg/3000,-2,2) + 10*frn_streak3
   개인만 순매수인 날은 추가 -8
4) 거래대금 (0.15): amt_mult = 당일/20일평균
   amt_score = 50 + 30*log2(clamp(amt_mult,0.4,4)), chg_pct<0 이면 100-amt_score 로 반전
5) 마감 동시호가 (0.10): call_drift = (종가-15:20지수)/15:20지수*100
   call_score = 50 + 25*clamp(call_drift,-1,1)
   지수 리밸런싱일/옵션만기일이면 이 항목 제외하고 가중치 재배분
6) 마감 후 재료 (0.10): 호재-악재 개수, 야간선물 등락률, 미국선물 등락률
   news_score = 50 + 10*(호재-악재) + 15*clamp(night_fut,-1.5,1.5)/1.5 + 10*clamp(us_fut,-1,1)
   마감 후 유상증자/CB 공시는 단일 항목 -25

모든 서브스코어는 clamp(0,100).
total = 0.20*close + 0.20*breadth + 0.25*flow + 0.15*amt + 0.10*call + 0.10*news

익일 확률: p_up = 1/(1+exp(-(total-55)/10)), 클리핑 0.20~0.80
보정: 지수 상승 + adv_ratio<0.4 이면 p_up -= 0.05
      익일 FOMC/CPI 또는 만기일 익일이면 p_up = 0.5 + (p_up-0.5)*0.7

결측 처리:
- 항목 1개 결측 → 가중치 비례 재배분, missing 리스트에 기록
- flow(0.25) 결측은 2개 결측과 동일 취급
- 2개 이상 결측 → total=None 반환, 계산된 서브스코어만 반환

반환은 dataclass: total, p_up, p_down, subscores(dict), missing(list), grade(str), provisional(bool)
등급: 75+ 강세 / 65-74 우호 / 55-64 중립 / 45-54 약세 / <45 위험

pytest 테스트도 같이 작성. 경계값(결측, clamp 상하한, 반전 조건, 확률 클리핑)을 반드시 커버.
```

## 3. 채점·복기 엔진 (review)

```
마감 후 실행되는 채점·복기 모듈을 만들어줘.

기능 1) 아침 점수 채점
- scores 테이블에서 phase='morning', 당일 레코드를 읽는다
- daily_market에서 당일 kospi_close vs kospi_prev로 actual_dir 계산
- 방향 적중 여부, 등급 적중 여부, 브라이어 항 계산
- 최근 30거래일 롤링 브라이어 스코어 갱신

기능 2) 마감 점수 채점 (익일 실행)
- scores 테이블 phase='close' 전일 레코드 vs 당일 실제 방향 비교
- 동일하게 브라이어 갱신

기능 3) 매매 복기
- trades 테이블에서 당일 레코드 조회
- discipline = (stop_respected + timestop_respected + (plan_deviation=='없음')) / 3
- 준수율 100% + 손실 → "정상, 규칙 유지" 메시지
- 준수율 <=0.66 + 수익 → "위험: 규칙 위반이 보상받음" 경고 (가장 강한 경고)
- 3일 연속 준수율 < 0.8 → 익일 게이트 비중 0.5배 플래그를 DB에 기록

기능 4) 항목별 오차 분석
- 각 서브스코어와 실제 방향의 상관을 최근 30일로 계산
- 실제와 가장 어긋난 항목 1개를 반환

출력은 마크다운 리포트 문자열. 숫자는 소수점 둘째 자리까지.
```

## 4. 익일 후보 스크리너 (screener)

```
마감 데이터로 익일 관심종목을 뽑는 스크리너를 만들어줘.

필터 (전부 AND):
- 등락률 3% 이상 15% 이하
- 거래대금 500억원 이상
- 거래대금 / 20일 평균 >= 2.0
- close_pos = (종가-저가)/(고가-저가) >= 0.7
- 시가총액 1000억원 이상
- 종가 > 5일 이동평균
- 마감 후 유상증자/CB/감자/대주주매도 공시 없음 (DART 폴링 결과 조인)
- 관리종목/투자경고/정리매매/스팩/우선주 제외
- 상한가 마감은 후보가 아닌 '관찰' 태그로 분리

정렬:
rank_score = 0.4*normalize(거래대금배수) + 0.3*close_pos + 0.2*sector_leader_flag + 0.1*foreign_buy_flag
상위 5개만 저장.

각 후보마다 아래 4개를 반드시 채운다. 하나라도 비면 후보에서 제외한다:
- entry_type: '갭눌림' | '전고돌파' | '눌림목반등' 중 하나
- stop_price: 진입 유형별 규칙에 따라 계산
- target_price
- invalidation: 무효화 조건 문자열

candidates 테이블에 저장. DART 폴링에서 악재 공시가 뒤늦게 뜨면
disqualified=true, disq_reason 채우고 텔레그램으로 정정 알림 발송.
```

## 5. 리포트 발송 (notifier)

```
마감 리포트를 텔레그램으로 보내는 모듈을 만들어줘.

리포트 구성 순서:
1. 한 줄 결론
2. 마감 점수 / 익일 상승 확률 / 익일 하락 확률
3. 항목별 점수표 (항목, 관측값, 점수, 코멘트)
4. 아침 점수 채점 결과 + 누적 브라이어
5. 주도 섹터 / 소외 섹터 / 특징주 3~5개
6. 매매 복기 (준수율, 개선점 1~2개)
7. 익일 시나리오 (상승/하락/트리거 이벤트)
8. 익일 관심종목 (타점·손절·목표·무효화 4종 세트)
9. 주의 신호
10. 하단에 "투자 판단의 참고 자료이며 투자 권유가 아님"

요구사항:
- 텔레그램 4096자 제한 → 섹션 단위로 분할 발송, 잘라내지 말 것
- 잠정치 기반이면 제목에 [잠정] 배지, 확정치 반영 후 [정정] 메시지 별도 발송
- 데이터 부족(2개 이상 결측)이면 점수 대신 "데이터 부족" 표기하고 계산된 서브스코어만 발송
- 발송 실패 시 3회 재시도 후 로컬 파일로 저장하고 에러 알림
```

## 6. 대시보드 (Next.js)

```
Next.js App Router + Tailwind로 마감 대시보드를 만들어줘.

화면 구성:
- 상단: 날짜 선택기, 다크모드 토글, [잠정]/[확정] 배지
- 히어로: 마감 점수 큰 숫자 + 등급, 익일 상승/하락 확률 도넛
- 항목별 6개 서브스코어 가로 막대 차트 (결측 항목은 회색 빗금 처리)
- 투자자별 수급 막대 (외국인/기관/개인/프로그램, 양수 초록 음수 빨강)
- 업종별 등락 히트맵
- 익일 관심종목 테이블 (종목, 타점유형, 손절, 목표, 무효화)
- 채점 섹션: 최근 30일 브라이어 스코어 추이 선그래프, 적중률
- 복기 섹션: 규칙 준수율 추이, 매매 목록

데이터는 FastAPI /api/close/* 엔드포인트에서 SWR로 가져온다.
차트는 recharts. 모바일 반응형 필수.
증권사 원천 시세를 외부 공개하지 않도록, 공개 배포 시에는 점수·확률만 노출하고
개별 종목 호가·체결 데이터는 인증된 세션에서만 보이게 한다.
```

## 7. 종가 베팅 파이프라인 (preclose + overnight-guard)

```
역할: 한국 주식 종가 베팅 자동화 파이프라인 개발자

`closing_bet/` 패키지를 만든다. 기존 collector/scoring 모듈을 재사용한다.

[모듈]
closing_bet/
  screener.py    14:30 조건검색 → 관찰 리스트
  watcher.py     14:30~15:10 탈락 감시
  judge.py       15:15 최종 판정
  executor.py    15:19 / 15:26 분할 주문
  guard.py       16:00~20:00 DART + 미국선물 감시
  exit.py        익일 09:00~10:00 청산

[screener.py]
- 증권사 조건검색 API로 후보 수집. 필터(전부 AND):
  등락률 2~15%, 거래대금 300억 이상 OR 최근 5일 내 300억 장대양봉 1개 이상,
  거래대금/20일평균 >= 2.0, (현재가-저가)/(고가-저가) >= 0.7,
  현재가 > 5일선, 시총 1000억 이상
- 제외: 관리·경고·정리매매·스팩·우선주·ETF·ETN, 당일 상한가, 만기일 전체 스킵
- candidates 테이블에 phase='preclose_screen'으로 저장, 텔레그램 발송

[watcher.py]
- 5분 폴링. 탈락 조건: 고가 대비 -3% 이탈 / 5일선 이탈 / 섹터 대장주 붕괴
- 탈락 시 status='dropped', reason 기록 후 알림

[judge.py]
- 15:15 정각 실행. 체크 4개:
  1) 종가위치 >= 0.7  2) 매수 호가잔량 > 매도 호가잔량
  3) preclose_1515 점수 >= 70  4) 미국 지수선물 > -0.5% (단일 거부권)
- 통과 종목 최대 2개. 텔레그램에 인라인 버튼("승인"/"취소")으로 발송
- 승인 시 approval_tokens 테이블에 1회용 토큰(유효 10분) 발급

[executor.py]
- 유효한 승인 토큰이 없으면 예외를 던지고 절대 주문하지 않는다
- 15:19: 계획 수량의 50%를 접속매매 지정가로 주문
- 15:26: 나머지 50%를 동시호가로 주문.
  * "반드시 담기" 플래그면 상한가 지정가로 제출 (체결은 종가로 됨)
  * 아니면 15:19 종가 +0.5% 지정가
  * 직전 예상체결가가 15:19 종가 대비 -1% 이하면 전량 취소하고 종료
- 15:29 이후에는 어떤 주문·정정·취소도 실행하지 않는다 (하드 가드)

[guard.py]
- 보유 포지션이 있을 때만 활성
- 16:00~19:00 5분 간격 DART OpenAPI 폴링.
  키워드: 유상증자, 전환사채, 신주인수권부사채, 감자, 최대주주 변경,
  대주주 지분 매각, 횡령, 배임, 감사의견 거절, 거래정지
  → 감지 시 즉시 알림 + 애프터마켓 청산 지시
- 18:00~19:00 15분 간격 ES=F/NQ=F 확인. -1.0% 이하면 절반 청산 알림
- 애프터마켓 주문은 지정가만 허용. 시장가 주문 경로를 코드에서 아예 제거.
  1회 주문 수량은 해당 호가 잔량의 30%를 넘기지 않도록 분할

[exit.py]
- 익일 08:30~09:00 장전 예상체결가 -3% 이하면 시가 전량 청산 플래그
- 09:00 시가 기준 분기:
  +3% 이상 → 시가 절반 익절, 잔량 09:30까지
  +1~3%   → 09:00~09:30 3분할 익절
  -1~+1%  → 09:30까지 관찰, 5분봉 음전 시 전량
  -1% 이하 → 시가 전량 손절
- 10:00 타임스톱: 잔량 무조건 전량 청산

[요구사항]
- 모든 주문 함수는 dry_run 파라미터를 받고 기본값 True
- 주문 전후 상태를 trades 테이블에 반드시 기록 (주문 실패도 기록)
- 휴장일·만기일 테이블 체크를 모든 진입점에 넣는다
- pytest: 승인 토큰 없이 주문 시도, 15:29 이후 주문 시도,
  만기일 실행, 예상체결가 -1% 컷 4개 케이스를 반드시 커버
```
