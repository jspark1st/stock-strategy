# 전일 마감 판단 재평가 (장전 뉴스 + 장 초반 수급 기반)

이 스킬은 **`market-close-review`의 짝이자 후속 단계**다. 의사결정의 시작점은 항상 마감 스킬이다 —
전일 마감에 `market-close-review`가 확정한 지수 방향성 판단(마감 점수·p_up/p_down·게이트 비중)을
다음날 아침 실제 시장 데이터로 **재평가**해 승인(confirm) / 축소(reduce) / 취소(cancel)를 판정한다.

**전일 마감 결과 없이는 독립적으로 새 시장분위기 점수를 내지 않는다.** 재평가 대상은
**지수(코스피/코스닥) 방향성**이며, 개별 종목 후보는 `market-close-review`가 전담한다.
상세 로직은 `references/reassessment.md`를 반드시 읽는다.

## 언제 사용하는가

- "어제 마감 판단 오늘 아침 기준으로 재평가해줘", "어제 종가 베팅 유지해도 돼?"
- "오늘 장 분위기 점수로 알려줘", "장전 뉴스 브리핑 해줘" (→ 전일 마감 데이터를 먼저 요청)
- "상승 확률 / 하락 확률 대시보드 만들어줘"
- "퍼플렉시티 API + 증권사 API 연동해서 시황 수집 파이프라인 설계해줘"
- "단타 후보 종목 스크리닝 룰 만들어줘", "고수들 방식대로 아침 매매 루틴 짜줘"
- "Codex/Cursor로 구현할 수 있게 코드 설계안 뽑아줘"

## 기본 원칙

1. **역할 분리를 반드시 지킨다.**
   - Perplexity/뉴스 API = 재료 해석·요약·태깅 (초단위 시세 소스로 쓰지 않는다)
   - 증권사 Open API/WebSocket = 원천 실시간 데이터 (호가·체결·거래량·예상체결)
   - 자체 스코어링 엔진 = 판단
   - 대시보드/봇 = 전달
2. **모든 출력은 한국어**, 개념 설명보다 실행 가능한 설계·워크플로우 우선.
3. **점수는 항상 근거 항목별로 분해**해서 표로 보여준다. 총점만 던지지 않는다.
4. **투자 조언이 아님을 명시**하고, 손절 기준·리스크를 함께 적는다.
5. 수치·뉴스는 반드시 최신 데이터로 확인한다. 기억에 의존해 시세를 쓰지 않는다.

## 표준 워크플로우

### A. 재평가/시황 브리핑 요청일 때

0. **전일 마감 데이터 확보가 최우선.** 사용자가 아직 전일 마감 요약을 붙여넣지 않았다면,
   `references/reassessment.md` 0장의 템플릿으로 먼저 요청한다. 마감 데이터 없이 진행하지 않는다.
1. **오늘 아침 데이터 수집**
   - `finance` 커넥터 또는 `finance/finance-markets` 스킬로 KOSPI/KOSDAQ, 원달러, 미국 3대 지수, 나스닥 선물, VIX, 업종별 흐름 확인.
   - 웹 검색으로 장전 뉴스: 실적·공시, 정책, 해외증시 마감, 예정 경제지표, 섹터 재료.
   - 가능하면 증권사 API 수집분(예상체결·갭·체결강도)을 사용자로부터 받거나 파이프라인 값을 읽는다.
2. **아침 점수 계산**: `references/scoring.md`의 가중치와 공식을 그대로 적용해 `open_score`/`open_p_up`을 낸다.
3. **재평가 판정**: `references/reassessment.md` 3장의 승인/축소/취소 로직을 전일 마감 데이터와 결합해 적용한다.
4. **출력 포맷**: 아래 "출력 형식" 섹션의 표 구조를 따른다.
5. **종목 후보를 함께 요구하면** `references/pro-playbook.md`의 3장 필터와 4장 타점 규칙을, 재평가 판정이 허용하는 개수(6장 표)까지만 적용한다.

### B. 시스템 구축 요청일 때

1. 대상 시장(국내 전용 / 미국 포함)과 실행 환경을 먼저 확정한다.
2. `references/architecture.md`로 수집→저장→점수→표시 아키텍처 제시.
3. `references/broker-api.md`로 한국투자증권·LS증권 등 증권사 API 연동 절차·엔드포인트 정리.
4. `references/codex-prompts.md`의 역할 분배 프롬프트를 그대로 제공.
5. 실제 배포/키 저장 방법을 물으면 `references/secrets-setup.md`로 로컬 `.env`, GCP Secret Manager, systemd, Docker Compose 각 방식을 안내한다.
6. 프로토타입이 필요하면 `assets/dashboard-template.html`을 복사해 수정 후 배포한다.

## 점수 체계 (요약)

| 항목 | 지표 | 비중 |
|---|---|---|
| 장전 뉴스 강도 | 호재/악재 키워드, 섹터 확산도 | 25% |
| 시초가 갭 | 전일 종가 대비 갭 방향·크기 | 20% |
| 동시호가 반응 | 예상체결가 변화, 매수/매도 우위 | 20% |
| 장 초반 거래량 | 5분 거래량 / 20일 평균 배수 | 20% |
| 수급 강도 | 체결강도, 대금 증가율, 상위주 동반성 | 15% |

해석 기준: **75점 이상 = 공격적 단타 가능 / 55~74점 = 선별 진입 / 54점 이하 = 관망**.
상세 공식과 확률 변환식은 `references/scoring.md` 참조.

## 실전 게이트 (반드시 적용)

**이제 게이트는 아침 점수 단독이 아니라 `references/reassessment.md` 3장의 재평가 판정 결과로 정한다.**
마감 방향과 아침 방향이 어긋나면(방향 불일치) 아침 점수가 아무리 높아도 취소된다 — 이게 기존 아침 단독
게이트와 가장 크게 달라진 지점이다.

```
취소 → 신규 진입 차단, 관망 알림만
축소 → 후보 최대 1개, 비중 50% 축소
승인 (open_score 55~74) → 후보 최대 2개, 정상 비중
승인 (open_score 75 이상) → 후보 최대 3개, 공격적 대응 허용
```

종목 후보를 낼 때는 항상 **진입 타점 유형(시가 눌림 / 시가 돌파 / 추세 추종), 손절가, 목표가, 무효화 조건**을
함께 명시한다. 이 4개가 없으면 후보로 내지 않는다. 상세 규칙은 `references/pro-playbook.md`.

**일봉 기준 손절·목표가(스윙/오버나이트 후보)는 ATR 기반으로 계산한다.** 초단타(당일 청산)의 −1.5~−2% 고정 손절은 `references/pro-playbook.md` 6장을 그대로 쓰되, 하루를 넘기는 후보는 일봉 ATR(14)×배수로 손절·목표 거리를 정하고 그 손익비를 `p_up`/`p_down`과 결합해 손익분기 승률·기대값·켈리 비중을 계산한다. 공식은 `references/atr-risk-sizing.md` 참조.

## 출력 형식

재평가 브리핑은 항상 아래 순서로 낸다.

1. **한 줄 결론** — 오늘 재평가 판정(승인/축소/취소)과 대응 강도.
2. **전일 마감 총점/p_up vs 오늘 아침 점수/p_up / 최종 판정** — `references/reassessment.md` 7장 표 그대로.
3. **항목별 점수표** — 항목, 관측값, 점수, 코멘트 (아침 점수 구성 항목별).
4. **주요 재료 3~5개** — 출처 링크 포함.
5. **주의 신호** — 선반영, 오보 가능성, 지수 이벤트, 만기일 등.
6. **실행 규칙** — 판정별 대응(유지/절반청산/즉시청산), 손절 기준, 관망 조건.

시각화가 도움이 되면 `visualize` 스킬을 로드해 점수 게이지·항목별 막대 차트를 추가한다.

## 리스크·법적 주의

- 증권사 API 약관상 **데이터 재배포 제한**을 확인한다. 외부 공개 대시보드에 원천 시세를 그대로 노출하지 않는다.
- 뉴스 기반 자동매매는 오보·중복기사·선반영 리스크가 크다. 뉴스는 필터이지 트리거가 아니다.
- WebSocket 지연·끊김은 잘못된 점수를 만든다. 재접속·하트비트·버퍼링·장애 시 점수 보류 로직을 넣는다.
- API 키·계좌 토큰은 서버 환경변수/시크릿 매니저로만 관리하고 프론트에 절대 노출하지 않는다.
- 산출물에 "투자 판단의 참고 자료이며 투자 권유가 아님"을 표기한다.
